# Voiceover script: The requirements tracker

## tr-overview

Every relevant requirement is listed by Part. Assign by discipline fills in the usual owner for each row.

## tr-assign

Each row now has a responsible designer, and the principal designer can see any gaps.

## tr-relevance

If a requirement doesn't apply, the principal designer records why.

## tr-my

Each designer gets a list of just their own requirements.

## tr-answer

The designer writes their own project-specific answer. The principal designer can't write it for them.

## tr-progress

The principal designer sees progress across every Part.

## tr-evidence

And the tracker goes into the evidence pack, with the audit trail.
